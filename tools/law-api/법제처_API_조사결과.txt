법제처 API: 제공 API 종류 및 수집 가능한 데이터 범위
Risk 대응 AI Agent 프로젝트 / 확인일: 2026-10-30

1. 이번 작업의 결과물

우리 프로젝트에서 다루는 법률·시행령·고시·지침을 Open API로 호출하여 JSON 원문을 모으고, 출처·버전·수집시각을 붙여 공유하는 작업이다. 요청 예제와 수집 코드도 함께 제공한다.

전체 문서 후보는 25개이며, 사용 목적을 좁혀 이번에는 17개를 실제 수집하고 8개를 보류했다. 상세한 선정 이유는 collection_policy.json과 수집결과_읽는법.txt에서 확인한다. 전체 후보 25개의 구성은 다음과 같다. 기본 법령 8개, 관련 고시·지침 6개, 사고 조건별 추가 법령 6개, 기간 계산 규정 2개, 제재·조사 관련 행정규칙 3개로 구성했다. 문서 수집 범위이며 모든 사고에 전부 적용한다는 의미는 아니다.

확인 상태:
- 공식 상세 가이드 33개를 선별·확인했다. 이 중 JSON 지원 API 31개를 요청 예제로 묶었다.
- 공식 공개 예제의 OC=test 호출은 HTTP 200과 사용자 인증 실패 JSON을 반환했다.
- 등록한 OC의 JSON 권한을 수정한 뒤 실제 수신에 성공했다. 법령 목록·본문, 행정규칙 목록·본문, 체계도, 위임 관계의 6개 API를 실제 검증했다.
- 실제 수집 결과는 본문 17개, 체계도 5건, 위임 관계 10건이다. 공유 묶음의 수집목록.json과 수집기록 폴더에서 출처·버전·해시를 확인할 수 있다. 판례·결정례 본문 수집은 0건이다.

2. 제공 API를 데이터 종류로 분류

[법령 원문: 우선 수집]
API: eflaw 목록·본문, eflawjosub 조항호목
받는 데이터: 법령명, 법령ID, 버전 일련번호, 공포일·시행일, 소관부처, 조·항·호·목 원문, 부칙, 별표, 개정문·이유 등.
프로젝트 용도: 신고·통지·보고·조치·제재의 근거 원문을 저장하고 답변에서 정확한 조문을 인용한다.
사용 방법: 목록에서 정확한 문서명을 찾고 법령일련번호(MST)와 시행일자(efYd)로 본문을 조회한다.
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdInfoGuide

[행정규칙: 우선 수집]
API: admrul 목록·본문
받는 데이터: 고시·훈령·예규·지침 등의 이름, 종류, 발령기관·번호·일자, 시행일자, 본문, 부칙, 별표 및 첨부 링크.
프로젝트 용도: 법률·시행령에서 위임한 세부 기준, 시설 관리 기준, 개인정보 안전조치 등을 보완한다.
사용 방법: 목록의 행정규칙일련번호를 본문 요청의 ID로 전달한다. 행정규칙ID는 별도 변수 LID다.
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=admrulInfoGuide

[법령 사이의 관계: 함께 확인]
API: lsStmd 체계도, lsDelegated 위임법령, thdCmp 3단비교
받는 데이터: 법률·시행령·시행규칙의 연결, 위임·인용 대상 조문, 위임된 행정규칙의 식별자·제목·링크 등.
프로젝트 용도: 근거 조문에서 세부 절차를 정한 하위 규정으로 이동하고, 함께 확인할 자료를 찾는다.
한계: 법 적용의 모든 조건이나 여러 신고 의무의 대체·병행 관계까지 정리된 데이터는 아니다. 3단비교 자료가 없는 문서도 있다.
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsDelegated
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=thdCmpInfoGuide

[별표·서식: 필요 자료 확보]
API: licbyl 법령 별표·서식, admbyl 행정규칙 별표·서식
받는 데이터: 서식명·번호·소속 문서·유형·일자와 HWP/PDF 링크 등. 본문 API에도 별표 내용과 파일 링크가 포함될 수 있다.
프로젝트 용도: 신고·보고에 필요한 제출 내용, 양식, 제재 기준표 확인.
한계: JSON으로 서식의 메타데이터와 링크를 받는 것이며, 첨부파일의 레이아웃·입력란이 완성된 폼 데이터로 변환되는 것은 아니다. 파일 자체의 다운로드·해석은 별도 작업이다.
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsBylListGuide
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=admrulBylListGuide

[개정·버전: 갱신 및 과거 사건 확인]
API: lsHstInf 변경 목록, lsJoHstInf 일자별·조문별 이력, oldAndNew 신구비교, law 공포 기준 법령
받는 데이터: 변경된 법령·조문, 개정일·시행일, 변경 사유, 신구 내용과 관련 링크.
프로젝트 용도: 이미 저장한 근거가 바뀌었는지 찾아 재수집·재검토하고, 과거 사건의 근거 버전을 관리한다.
주의: 이름이 비슷한 lsHistory 목록·본문은 공식 가이드상 HTML 전용이다. JSON 연혁 검색은 eflaw 목록의 nw=1과 해당 버전의 MST·efYd를 활용한다.
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsChgListGuide
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsDayJoRvsListGuide
출처: https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsHstListGuide

[결정례·법령해석·판례: 설명 근거 확장]
API: ppc 개인정보보호위원회, kcc 방송미디어통신위원회, prec 판례, expc 법령해석례, msitCgmExpc 과기정통부 법령해석

3. 우리 프로젝트의 수집 문서

기본 8개:
① 정보통신망 이용촉진 및 정보보호 등에 관한 법률 + 시행령
   침해사고 신고·통지, 원인 분석·조치, 대응 매뉴얼, 피해구제와 제재.
② 개인정보 보호법 + 시행령
   개인정보 사고 통지·신고, 보호조치, 손해배상과 제재.
③ 방송통신발전 기본법 + 시행령
   방송통신재난 보고·대응, 공동이용과 제재.
④ 전기통신사업법 + 시행령
   서비스 중단 고지, 손해배상, 이용자 보호와 제재.

관련 고시·지침 6개:
- 표준 개인정보 보호지침
- 개인정보의 안전성 확보조치 기준
- 주요통신사업자의 통신시설 등급 지정 및 관리 기준
- 과학기술정보통신부 소관 주요정보통신기반시설 보호지침
- 재난 시 무선통신시설 공동이용 범위 및 절차에 대한 고시
- 전기안전관리자의 직무에 관한 고시

사고·시설 조건별 추가 6개:
- 정보통신기반 보호법 + 시행령: 지정된 주요정보통신기반시설 관련 상황
- 재난 및 안전관리 기본법 + 시행령: 재난 범위·기관 지정과 해당 의무 확인
- 소방기본법: 화재·구조 상황
- 산업안전보건법: 작업중지·대피·산업재해 상황

기간 계산의 공통 규정 2개:
- 민법
- 행정기본법
개별 법령의 기간 특칙과 함께 검토한다.

제재·조사 설명 확장 후보 3개:
- 개인정보 보호법 위반에 대한 과징금 부과기준
- 개인정보 보호법 위반에 대한 과태료 부과기준
- 개인정보 보호위원회의 조사 및 처분에 관한 규정

기존 프로젝트 조사에 등장한 조문 번호는 project_scope.json의 article_focus에 기록했다. 최신 법령 버전 및 조문 유효 여부는 실제 수집 후 확인한다. 본문은 일부 조문만 자르지 않고 부칙과 함께 보존한다. 필요한 시행규칙·추가 고시는 체계도와 위임 관계를 확인하여 보완한다.

4. JSON 수집 시 놓치면 안 되는 부분

- JSON은 응답 형식이다. 요청에 type=JSON을 넣는다. 수집 코드의 언어가 JSON이어야 하는 것은 아니다.
- 법령 검색 eflaw는 nw=3이 현행이고 기본값은 전체다. 행정규칙 admrul은 nw=1이 현행이다.
- 법령ID와 법령일련번호(MST)를 구별한다. eflaw 본문에 ID를 주면 현행 본문을 조회하고 efYd는 무시된다. 버전을 지정하려면 검색 결과의 MST·efYd를 사용한다.
- efYd에 임의의 사고 날짜만 넣으면 그날 적용되는 법이 자동으로 결정되는 구조가 아니다. 과거 사건은 연혁 버전, 부칙, 조문별 시행일을 함께 확인한다.
- 공포일과 시행일은 다르다. 공포된 개정법을 현재 사건의 근거로 바로 사용하면 안 된다.
- HTTP 200이어도 인증 실패 JSON이 올 수 있다. 실제 문서 내용이 있는지 확인해야 한다.
- 목록은 페이지를 순회한다. display 최대 100은 해당 변수가 문서에 있는 API에만 적용한다.
- JSON에는 문자열·중첩 구조·링크가 들어갈 수 있다. 수신 후 실제 구조를 확인하고 일관된 내부 형식으로 변환한다.

5. API 원문으로부터 별도로 만들어야 하는 데이터

API에서 수집: 법령·행정규칙 원문, 버전·시행일, 부칙, 관계, 결정례, 첨부 링크.
서비스에서 구조화: 어떤 사실이면 어떤 의무가 생기는지, 누구에게 무엇을 언제 제출하는지, 예외·보완·대체 관계, 근거 조문과 검토 상태.
사건별 입력: 인지 시각, 피해 범위, 사고 원인, 시설·사업자 조건, 실제 신고 내역과 증빙.

예를 들어 기한 표현이 조문 원문에 들어 있더라도 API가 사건 인지 시각을 받아 마감 시각을 계산해 주지는 않는다. 원문 수집 이후 의무·조건을 추출하고 확인하는 단계가 필요하다.

KISA·개인정보위의 웹 신고 안내와 업무 매뉴얼, SKT 이용약관·내부 규정·연락망·시설 지정 정보, 실제 접수증은 별도 자료로 확보해야 한다.

6. 실제 호출과 공유 방법

API 신청 시 인터넷 분야에서 필요한 목록·본문의 JSON을 선택한다. 등록한 인증값 OC와 호출 서버의 IP·도메인을 확인한다. 모바일 본문은 HTML만 제공된다고 안내되어 있다.
신청 안내: https://open.law.go.kr/LSO/usrJoin.do

인증값은 law-api-research/.env에 LAW_API_OC=등록한값 형식으로 저장할 수 있다. 이 파일은 공유하지 않는다.

선정된 17개 문서 수집:
python3 law_api.py collect --profile initial

체계도·위임 관계 수집과 조문·서식 후보 정리:
python3 collect_related.py --input downloads/실행폴더
python3 prepare_dataset.py --input downloads/실행폴더

수집이 완료된 실행 폴더를 공유용 ZIP으로 만들기:
python3 package_data.py --input downloads/실행폴더 --output 법제처_JSON_수집자료.zip

완성 ZIP의 구성:
- 원본_JSON/: 문서별 실제 API 응답
- 법령_통합.json: 전체 본문과 버전·출처를 하나로 묶은 파일
- 수집목록.json: 수신 문서 수와 문서별 수집 정보
- 수집기록/: 원본 검색 결과, 선택한 버전, 본문과 요청 기록
- 요청예제_수집코드/: Python 코드, Postman JSON 요청 예제, 설명

인증 실패나 문서 누락이 있으면 수집 완료 파일로 포장하지 않는다. 각 API의 정확한 요청변수·출력 필드·출처는 api_catalog.json에서 확인할 수 있다.
